Instalar

Comece localmente, com segurança

O caminho mais curto é abrir a interface de desenvolvimento no seu computador. Ele não toca em impressoras, não cria contas e não precisa de Docker.

Prévia de desenvolvimento. A Fase 0 está em andamento. O projeto não é uma versão pronta para operar uma farm em produção, e nada aqui está comprovado em hardware físico (not proven on hardware). Veja o que cada etapa comprova.

1. Execute a interface localmente

Você precisa de Node.js 22.22.3+ na série 22.x ou 24.22.2+ na série 24.x, e de npm, que vem com o Node.js. O arquivo .nvmrc fixa o Node 22.23.5. 

git clone https://github.com/bloodf/Open3DFarmManager.git
cd Open3DFarmManager
npm ci --ignore-scripts
npm run dev

Abra http://127.0.0.1:3000. Você verá a interface de desenvolvimento. Esse comando não cria contas, não configura banco de dados e não conecta impressoras. Autenticação e integrações começam desabilitadas e exigem configuração própria. A rota /farm está disponível sem feature flag.

2. Verifique antes de configurar

Rode a verificação local do repositório: formatação, tipos, testes e builds. Os testes de interface precisam do build produzido por ela. 

npm run check:all

npx playwright install chromium
npm run test:e2e

Os testes automatizados nunca enviam comandos a impressoras físicas. Para reproduzir os jobs da CI, consulte CI local.

3. Sem Docker e sem rede externa

O guia de desktop leva uma máquina até uma página da farm com impressoras simuladas. Exige Google Chrome e PostgreSQL 17+; Go 1.26+ é opcional e serve só ao helper RTSP. 

npm run build
npm run desktop:check -- --only app-smoke
npm run desktop:check -- --list

Os simuladores rodam como processos de teste em loopback. Detalhes e limites em docs/DESKTOP.md (em português) e no guia do simulador Klipper.

4. Hospedagem própria

O guia de hospedagem implanta uma aplicação e o seu banco PostgreSQL dedicado, em uma VM Linux limpa com Docker Engine e o plugin Compose, com um nome DNS e um proxy reverso com certificado TLS confiável. Resumo das etapas:

  1. Preparar o deploy com a imagem de release e um arquivo .env privado.
  2. Inicializar segredos e o banco de dados, com um dono de migração dedicado.
  3. Configurar o proxy reverso com TLS válido e WebSocket.
  4. Criar o primeiro proprietário com o token de uso único.
  5. Parear um Connector contra um simulador.
  6. Habilitar cada subsistema opcional de forma deliberada.

Leia o guia completo de hospedagem própria (em inglês). Antes de atualizar, leia também o guia de atualização.

Cuidados desde o primeiro dia

  • Mantenha credenciais, .env e a pasta state/ fora do Git. Não coloque URLs de banco, tokens ou chaves em logs nem em pedidos de suporte.
  • Não exponha o PostgreSQL publicamente. Deixe desabilitado tudo o que não tiver as credenciais próprias: comandos de impressora originados por API, integrações em nuvem e cadastro público.
  • Comandos do navegador usam somente WebRTC. Pareie o primeiro Connector contra um simulador, nunca contra uma impressora física, e confira a impressão digital exibida pela CLI antes de aprovar.

O que cada etapa comprova

Testes locais, integração com fixtures, aceitação com simuladores e validação em hardware físico são evidências diferentes. Siga as etapas acima sabendo em qual delas você está.

  • Executável
    Interface de desenvolvimento e testes locais. Você pode executar e inspecionar. Isso não prova o comportamento com impressoras.
  • Em andamento
    Simuladores. Há simuladores Klipper com cenários de falha de rede. A aceitação do SV06 e do cenário de quatro ferramentas está pendente, e a aceitação completa da Fase 0 ainda não foi concluída. Veja o registro da Fase 0.
  • Pendente
    Impressoras físicas. A aceitação em hardware permanece aberta e é feita pelo proprietário do projeto, depois dos simuladores. O catálogo de compatibilidade marca capacidades como simuladas, documentadas ou não comprovadas; nenhuma está comprovada em hardware físico (not proven on hardware).
  • Pendente
    Produção. O projeto não é uma versão pronta para operar uma farm em produção. Implantação e controle de impressoras físicas exigem autorização separada.
