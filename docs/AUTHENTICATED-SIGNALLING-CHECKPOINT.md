# Authenticated signalling preparation

Status: protocol source only. The coordinator, database authority reader, network runtime and real WebRTC integration remain pending. No connection or command authority is granted by these modules.

The protocol has separate P-256 browser admission and role-specific RTC transcript domains. Browser admission uses a fresh server-owned transport UUID and a maximum 8,000 ms challenge. This UUID is separate from browser enrollment proof IDs. Account identifiers remain text. Nonces are exactly 32 cryptographically random bytes encoded as canonical, unpadded base64url. All timestamps are integer Unix milliseconds.

The strict RTC binding contains the browser P-256 public key and thumbprint, Connector Ed25519 SPKI and fingerprint, farm/agent/browser-key IDs, account ID, credential jti, transport UUID, both nonces, authoritative origin/audience, both DTLS SHA-256 fingerprints, and SHA-256 hashes of the exact UTF-8 final offer and answer SDP bytes. No line-ending normalization occurs. Connector creates the offer; browser creates the answer. A changed description requires a new transport context and proofs.

Signature bytes are UTF-8 of `Open3DFarmManager/rtc-session-proof/v1\0`, the literal role (`browser` or `connector`), `\0`, and canonical JSON of the strict binding. Browser signatures use ECDSA P-256/SHA-256 in 64-byte WebCrypto/P1363 format. Connector signatures use Ed25519. Both use canonical unpadded base64url. `BrowserRtcProof` and `ConnectorRtcProof` parse strict role-specific envelopes. The real Connector adapter must sign through its encapsulated identity; the portable CryptoKey primitive does not authorize private-key export.

Endpoints must compare their exact local/remote descriptions and the actual negotiated DTLS certificate against the authenticated binding. The protocol helper checks description bytes and pins; it cannot inspect a live DTLS certificate. A server-supplied frame or UUID alone is never an admission result.

The proposed prototype policy has an 8-second admission deadline and a separate, maximum 30-second read-only transport lifetime, further capped by current session and credential deadlines. Both endpoints must independently enforce local monotonic deadlines and reject late asynchronous callbacks after closure. Proof freshness permits admission; a consumed proof is not continuing authority. Passive server revalidation must not renew the login session or transport lifetime. The coordinator and endpoint timer enforcement are not implemented by this protocol checkpoint.

`commands_enabled` is always false for every identity. This includes UUID-compatible accounts. No command authorization, status, camera or command payload travels through the server signalling frame protocol. It accepts bounded SDP, direct ICE and close metadata only; relay/TURN candidates are rejected. A later integration must retain Connector safety and close into read-only behavior on expiry or failed current-state authorization. Remote revocation cannot be learned immediately by an offline Connector and does not stop an ongoing print.

Focused validation: four real Node crypto/protocol tests passed, covering both algorithms, cross-domain/role rejection, identity/context mutation, exact SDP mutation with unchanged certificate, strict limits and forbidden frames. Database reads, current-state revocation races, runtime admission, endpoint deadlines and native WebRTC behavior remain unvalidated here. No new grants, schema, HTTP routes or runtime wiring were added. A current-head integrated gate remains pending.
