# Command authorization prototype

The Connector verifies browser pause commands in the pause dispatcher and API-originated signed envelopes in `packages/connector/src/runtime/api-command.ts`. The admitted command is routed to the selected printer driver only after verification and local control checks. Driver-specific support and state guards still apply.

## Runtime rejection boundary

The v2 dispatcher takes no caller-built context. Authority is an opaque handle the dispatcher's own verifier admitted; a missing, forged, copied or revoked handle returns `invalid-authority`, and a printer binding outside the admitted assignment returns `scope`, both without a journal claim. Malformed or non-canonical frames return `invalid-command` before any other check.

Journal denials (`replay`, `assignment-busy`, `capacity`, `clock-regressed`, `rate-limited`, `storage-unavailable`) are returned by `claimCommand` as themselves. The dispatcher maps `replay` and `assignment-busy` to `replay` and `busy` and every other journal failure, including a closed journal or a throwing storage gate, to `storage`; no internal detail reaches the result. Each valid request makes at most one claim attempt; no retry is introduced. The dispatcher's rejection reasons are a closed TypeScript union. Tests: `tests/unit/command-fail-closed.test.ts`, `tests/unit/command-signing.test.ts`, `tests/node/security-regression.test.ts` and the Chromium specs `tests/e2e/command-boundaries.spec.ts` and `tests/e2e/command-signing.spec.ts`.

## Command authorization rule

Browser commands stay WebRTC-only with no TURN or HTTP fallback; API-originated commands are allowed only with an owner-granted scope, delivered as issuer-signed envelopes, and enforced by the Connector, which refuses unsafe or unauthorized commands with a reason. No automatic retry of uncertain commands, and never command physical printers in automated tests.

For browser capabilities and direct API printer actions, a valid telemetry list older than 120 seconds or reported without a send age can authorize only advertised stop actions (`pause`, `cancel`, and `emergency_stop`). With no controls list, browser capability issuance is denied and direct API basic actions still defer to the Connector. API `emergency_stop` requires the owner-granted `control:extended` scope and an advertised control. The Connector independently applies its local authorization and safety checks.

## Connector checks for API commands

API-originated commands travel via the integration API (`/api/integrations/v1`) and are delivered to the Connector as issuer-signed envelopes. The Connector enforces local safety and authorization independently before dispatching any command to a printer driver. An offline or isolated Connector fails closed on expired or unverified authority.

Verified resin artifact starts are not yet available in the production Connector: no qualified resin dispatch capability is wired into its runtime. Requests are refused unless such a capability is explicitly supplied; the existing synthetic test capability does not enable real printers.

When receiving an API-originated command envelope, the Connector executes the following checks in order and refuses any failing command with an explicit reason code:

1. **Envelope framing and canonical shape (`invalid-command`, `invalid-envelope`):**
   - Validates that the wire payload is canonical JSON within bounded frame limits (maximum 8 KiB).
   - Rejects duplicate keys, unescaped control characters, non-canonical encodings, or invalid UTF-8 sequences.
   - Verifies the presence and types of all required envelope fields: schema version, issuer identifier, farm ID, agent ID, printer ID, client/app ID, command ID, action, arguments, `issued_at`, `expires_at`, and nonce.

2. **Issuer signature verification (`invalid-signature`, `invalid-issuer`):**
   - Resolves the issuer public key from local trusted configuration (the farm's trusted issuer keyring), never from sender-provided headers or unverified payloads.
   - Verifies the cryptographic signature (ECDSA P-256 with SHA-256, IEEE P1363 encoding) over the canonical unsigned envelope bytes.
   - Refuses commands with invalid signatures, unresolvable keys, or untrusted issuers.

3. **Farm and Connector agent scope binding (`scope-mismatch`):**
   - Verifies that `farm_id` in the envelope matches the Connector's locally enrolled farm.
   - Verifies that `agent_id` matches the Connector's own authenticated agent identity.
   - Refuses commands targeted at other farms or other Connectors.

4. **Printer assignment binding (`unknown-printer`):**
   - Verifies that `printer_id` matches an active printer currently assigned and locally bound to this Connector.
   - Refuses commands targeted at unknown, unassigned, or foreign printer IDs.

5. **Owner-granted scope authorization (`unauthorized`, `scope-denied`):**
   - Verifies that the envelope carries an owner-granted scope authorizing the specific action; library print starts use `jobs:write`.
   - Refuses commands if the required scope was not granted by the farm owner for the calling application.

6. **Freshness and clock validation (`invalid-clock`, `command-expired`, `clock-window`):**
   - Validates monotonic time against system wall clock; detects and fails closed on backwards clock regression.
   - Verifies that `issued_at` falls within the allowed clock skew window (at most 60 seconds from current Connector reference time).
   - Verifies that `expires_at > now`; fails closed if the command envelope has expired.

7. **Durable replay protection (`replay`, `storage-unavailable`):**
   - Atomically records the unique `command_id` and `nonce` in the local SQLite replay database within a transaction prior to execution.
   - Refuses any previously observed `command_id` or reused `nonce` within the retention window.
   - Fails closed with `storage-unavailable` if disk capacity is exhausted or replay storage cannot commit.

8. **Rate limiting (`rate-limited`):**
   - Enforces the per-printer caps in [Rate limits](#rate-limits) in the command journal. There is no separate per-application cap.
   - A rate-limited API envelope is refused as `printer-busy`; the browser dispatcher reports `storage`. The journal's own reason is `rate-limited`.
   - Emergency stop bypasses the operational rate limit but still strictly enforces issuer signature, identity, freshness, and replay claim.

9. **Printer state and driver safety interlocks (`unsafe-state`):**
   - Checks the target printer's current local state before execution.
   - Refuses actions that violate physical safety invariants (e.g. starting a print when bed is not clear or printer is in an error/fault state; extruding below minimum extrusion temperature; cancelling or pausing a printer that is not active).
   - Refuses unsafe commands with a specific diagnostic reason.

10. **Single consumption and uncertainty policy:**
    - Consumes the replay claim exactly once; no automatic retry of uncertain commands.
    - If the physical dispatch result or connection to the printer driver fails or is ambiguous, the Connector records and reports uncertainty explicitly rather than retrying.

## Full printer control rules

These action rules apply at the Connector immediately before dispatch. They supplement envelope identity, scope, freshness, replay, and state checks above and never replace them. Roles come from authenticated local membership data, never command fields. Role order is operator < admin < owner; "operator or higher" means all three roles. Every action is refused in `unknown` state except `emergency_stop`; in `error` state only `emergency_stop`, `firmware_restart` and `confirm_collection` are admitted. `run_macro` stays owner or admin. This section does not grant any role access beyond what the issue or documented current behavior already allows.

Fail closed. If the printer state, homing state, configured limit, advertised object, file path or limiter state needed for a check is missing, stale, or cannot be read, the Connector returns a denial with a reason code (for example `unsafe-state`, `scope-denied`, `unauthorized` or `invalid-command`; see step 8 for rate limits) and does not dispatch. No denial is retried automatically.

In every printer state (stopped, printing or paused), the console refuses a line whose command name matches a configured `gcode_macro`, including a macro named `QUERY_*` and an override of an allow-listed command such as `M105`. The refusal sends nothing. The only exception is the Snapmaker U1 tool selection, which has its own guard.

On a declared Snapmaker U1, the script acknowledgement alone never reports `QUERY_*`, `M105`, `M114`, `M115` or `GET_POSITION` as `applied`. The command is `applied` only if the Connector also receives that command's report, in the Klipper format, after sending the line and before the acknowledgement. This covers `M105`, `M114`, `M115`, `GET_POSITION`, `QUERY_ENDSTOPS`, `QUERY_PROBE`, `QUERY_ADC` and `QUERY_FILAMENT_SENSOR`. Without a matching report, and for every other `QUERY_*`, the result is `outcome-unknown` with reason `state-unconfirmed`: the line was acknowledged but its effect is unconfirmed, and it is not retried. Moonraker broadcasts reports without a request ID, so a report of the same format caused by another source in that window (such as the temperature lines of a heater wait, or another client's query) cannot be told apart. The report is evidence that is not strictly correlated, and these formats have not been qualified on hardware.

At idle, the console accepts known status queries, the tuning commands above, and `M118`. It refuses macros, tool changes, coordinate resets, mode changes and arcs. `G0`, `G1`, `G28` (bare `X`, `Y`, `Z` axes, as for `home`), `BED_MESH_CALIBRATE` (homed axes and a configured mesh area inside the axis bounds), `M104`, `M109`, `M140` and `M190` require a fresh printer state and valid configured limits. A linear move is limited to 50 mm at 150 mm/s and 10 mm of filament. Extrusion requires a hot, extrusion-enabled tool, and heater targets must respect the configured `max_temp`. Motion and extrusion remain refused while printing or paused, except Z babystep and the console tuning allow-list above. Unhomed axes are always refused. Bounds come from Klipper `configfile`; missing or invalid bounds deny the command.

An idle console line is classified by the Connector, and a line it cannot classify is refused. That includes any `gcode_macro` other than a recognised Snapmaker U1 tool selection, and a command that an advertised `gcode_macro` of the same name overrides. Canonical homing (`G28` with bare axis letters) is built by the structured `home` action, with the U1 pairing and Z-only checks, and is refused when the printer advertises a `G28` macro that overrides it. A U1 `T0`-`T3` selection keeps its homed-axes and idle-state check. On a Snapmaker U1, canonical console homing and `T0`-`T3` use the same bounded physical-control result window as the `home` action (24 s, counted from the single write); a later acknowledgement is confirmed without a second write, and nothing is retried.

The `service` action is owner only, so an admin is denied a service restart. Config writes need owner or admin, so an operator is denied a save. A save sent with `restart: true` (the editor's save-and-restart button) also restarts the firmware under the `config_write` role: an admin can trigger that restart, and it counts both as a config save and against the Service restart cap. The `firmware_restart` action is open to operators in the states listed above.

### Rate limits

The command journal counts claims per printer over a sliding one-minute window, for browser and API commands together. For the shared allowance and the Bed mesh, Power and Config save caps, a claim counts even if a later guard refuses it. All actions share one allowance, except `exclude_object`, which has its own and is counted only once its write starts. The Bed mesh, Power, Config save and Service restart caps apply on top of the shared allowance. The journal fails closed if it cannot read its state.

The Service restart cap covers every printer restart the Connector sends: `service` (any operation), `firmware_restart`, and a config save or restore with `restart: true`. A save with `restart: true` must be within both the Config save and Service restart caps; when either is spent, the whole command is refused and nothing is saved.

Refused commands do not use up the Service restart cap: a claim recorded as not sent restarted nothing. A claim counts while it is in progress, once sent, and whenever its outcome is unknown, including a refusal that happens after the first write (for a save with restart, after the backup write starts, even if the restart itself was never requested). API envelopes cannot carry a restart action, so only browser commands use this cap.

An unconfirmed `firmware_restart` (in progress is not affected) keeps its printer busy for 60 seconds from the time its outcome is recorded as unknown, because the restart drops the state read-back. During that time only `emergency_stop` is admitted. The hold is then released, and a Connector restart releases it at once. The result stays `outcome-unknown`, the restart is never retried, it still counts against the Service restart cap, and every later command still needs fresh ready printer state. Other unconfirmed commands that hold a printer are not released this way.
