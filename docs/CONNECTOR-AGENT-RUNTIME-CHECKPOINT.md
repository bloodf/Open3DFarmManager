# Scoped Connector telemetry runtime checkpoint

The direct Node CLI now accepts `run --config <runtime.json> --credential-file <secret.json> --data-dir <dir>`. It reuses an existing identity, one existing `TelemetryQueue`, the maintained authenticated telemetry sender and `drainTelemetryOnce`. It starts read-only Moonraker collection and one serial drain loop. There is no identity initialization, pairing, credential refresh, command path, browser proxy, configuration reload or unauthenticated sender fallback in this command. The synchronous exported identity `main()` and standalone unscoped `collect` remain available.

## Local inputs

The strict runtime configuration has `version: 1`, `collection`, `assignments` and `telemetry`. `collection` uses the existing version 1 collection schema. Each explicit assignment contains exactly `assignment_id`, `farm_id`, `agent_id`, `printer_key` and `moonraker_origin`, validated by the maintained local printer-binding registry. Every configured printer must match one mapping by its exact opaque key and canonical origin; all mapping farm/agent values must match the local credential. Assignment UUIDs and printer keys remain separate. There is no URL-derived identity, server discovery or inference of current server authority.

`telemetry` contains the trusted HTTPS `/api/connector/telemetry` endpoint and the protocol audience, with optional `timeoutMs`, `retryMinMs`, `retryMaxMs` and `idleMs`. The maintained sender validates its endpoint and credential format before queue creation. Defaults are a 5000 ms request deadline, 1000–30000 ms retry bounds and a 500 ms idle poll. Deadlines are bounded to 100–60000 ms, retry bounds to 100–300000 ms, and idle polling to 100–5000 ms. New observations do not wake or shorten a pending retry deadline.

The separate credential document is exactly `{ version: 1, expected_fingerprint, approval }`. `approval` must parse as the existing approved `PairingPollResponse`, including agent, farm, device token and expiry fields. The expected fingerprint must match `loadExistingIdentity()`; this command never calls the identity initializer. The credential has a 16 KiB cap, and runtime configuration a 64 KiB cap. Both use the shared private regular-file reader with owner-only permissions, one link, final-symlink/FIFO rejection before reading, descriptor validation, nonblocking/no-follow open, bounded incremental reads, fatal UTF-8 and bounded duplicate-rejecting JSON parsing. Secret tokens are not read from environment variables or emitted in diagnostics.

These local inputs do not validate a JWT or prove a currently issued credential. JWT validity, expiry, revocation and current assignment authority remain server decisions through the maintained transport. Startup rejects expired local metadata, including a recheck after asynchronous imports. If its expiry is reached during operation, the runtime cancels active authentication attempts and stops starting new ones, while bounded local collection continues until shutdown. It does not renew or reread the credential.

## Durable queue scope

`run` uses the fixed `telemetry` directory and a private `scope.json` receipt containing exact farm, agent, fingerprint and the full assignment/key/origin mapping. Assignments sort by UUID code units before canonical serialization. On restart, the receipt must match before the queue constructor can recover, expire or compact records. Any previously existing telemetry directory without a valid receipt is rejected, even if its queue file is empty or its records would now expire. There is no adoption, filtering or discard to make a queue fit another scope.

Initial creation requires a new runtime-owned telemetry directory. Its parent is fsynced. After the queue constructor holds its exclusive lock, depth must be zero and every recovery-loss value clear. The runtime then creates and fsyncs `scope.pending`, publishes that complete inode through a no-clobber hardlink to `scope.json`, fsyncs the directory, removes the pending link and fsyncs again. Interrupted directory/log/marker creation requires explicit operator review; the runtime does not delete or adopt it. A surviving marker is rejected even when a final receipt also exists. Existing standalone `collect` refuses either scope receipt or interrupted marker before opening its own queue.

This protocol does not solve adversarial races by another process running as the same operating-system user. The existing queue API has no atomic create-new-only option shared with older standalone collectors. A competing initializer, stale lock or inconsistent initialization remains fail-closed for operator review. Stale queue locks are never automatically removed.

## Execution and shutdown

The collection extraction receives the already-open queue and never closes or independently opens it. The runtime owns its sole close operation. Existing snapshot callbacks still persist synchronously before queued diagnostics; unavailable events remain local diagnostics without fabricated progress. Sender invocations always obtain a fresh proof through the maintained sender while retaining durable queue event IDs until an exact accepted FIFO acknowledgement. Old, missing or malformed acknowledgements leave records queued.

An outer attempt has a deadline-bearing abort signal and monotonic, capped jittered retry timing. The runtime waits for the actual sender promise to settle even when the maintained drain returns cancellation first. It never overlaps another invocation or bypasses backoff when collection adds data. Internal HTTP 429 behavior remains entirely in the maintained sender. Queue/drain uncertainty aborts all collection, joins its sockets and the sender, closes the queue and returns a failure. Retention can evict an in-flight prefix; if this makes acknowledgement uncertain, the runtime stops for review rather than confirming delivery.

The bootstrap permanently sets both optional-WebSocket-addon disable flags before its first dynamic networking import. It does not restore flags or manipulate module caches. The existing Moonraker client retains its own compatible assignments. Pure runtime configuration imports neither it nor `ws`; the signalling/provider transport is unchanged. SIGINT/SIGTERM handlers remain owned by the CLI adapter and are removed after cancellation and joining. Diagnostics use bounded local schemas without tokens, printer keys, private paths or endpoints. Summaries retain collection and drain loss counts.

The existing subscription emits normalized observations after its UI-state deduplication. A future raw-status freshness callback must sit before that deduplication if a control driver needs every validated status receipt. This slice identifies that seam only; it does not implement drivers, commands, signalling or protocol changes.

## Evidence and pending gates

Focused source tests run the actual Node CLI against original synthetic Bun Moonraker and HTTPS telemetry fixtures. An ephemeral private test CA is created outside the repository and trusted with `NODE_EXTRA_CA_CERTS`; TLS verification is not disabled. The fixture uses the maintained challenge schema and proof payload to verify actual Ed25519 signatures, but its token and assignment authorization are synthetic. It is not the actual server JWT/current-assignment or PostgreSQL authorization path.

Tests cover lost acknowledgements and fresh proofs for the same durable IDs, scoped restart, exact FIFO completion, wrong scope and interrupted receipts with zero network, preservation of expired unbound records before constructor recovery, private credential limits and FIFO rejection, local expiry with continued collection, retry pacing despite new observations, storage uncertainty and SIGTERM during an in-flight request. Existing standalone collection regression tests cover the extraction. A module-load hook rejects networking imports from pure runtime configuration.

`bun test tests/unit/connector-agent-runtime.test.ts --max-concurrency 1` passed 10 groups and 108 assertions. `bun test tests/unit/moonraker-collect.test.ts --max-concurrency 1` passed 8 groups and 83 assertions. An owned-file `tsc --noEmit` configuration, targeted Prettier and whitespace checks passed. These results use Node 24.20.0 and Bun 1.4.2 against source modules; they do not establish packaged execution.

Production bundle execution, actual issued credential acceptance, packaged HTTPS/Nuxt/PostgreSQL integration, real server revocation/current-assignment checks, process power-loss testing and genuine Moonraker simulator acceptance remain pending coordinated windows. No dependencies were added, and no maintained sender, drain, queue, identity, control or protocol implementation was changed. No full repository gate, build, native WebRTC execution, PostgreSQL, Docker, browser, SSH, hardware or publication was performed by this slice.
