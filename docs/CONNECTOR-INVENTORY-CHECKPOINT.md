# Connector inventory verification checkpoint

The inventory endpoint lists farms visible to the signed-in account and the enrolled Connectors in a selected farm. It exposes only farm identifiers and Connector agent identifiers, fingerprints, and enrollment status. It is read-only and does not provide commands or live status.

The focused pagination test checks bounded limits, canonical cursors, repeated parameters, and unexpected parameters. The opt-in PostgreSQL fixture checks keyset pages, farm isolation, authorization under row locks, expiry after a lock wait, least-privilege grants, and unchanged enrollment status. It also signs in through the maintained authentication service, obtains its sealed host-only cookie, and carries that cookie over a task-owned loopback HTTP listener to the inventory request service and PostgreSQL. The listener is a test adapter, not the deployed Nuxt server. The HTTP checks also cover a short-lived session that expires after login and a real PostgreSQL runtime-role connection outage: the fixture disables login for its own role, terminates that role’s connections, verifies 503 responses for both reads, restores login, and verifies recovery. The admin connection remains healthy; no proxy fabricates a failure response.

The runner requires an explicitly identified disposable loopback PostgreSQL database named `fixture`, with the complete local migration catalog applied and its journal verified. It refuses a missing or modified journal. The caller owns database teardown and must set `INVENTORY_SYNTHETIC_TEST_DISPOSABLE=yes` and `INVENTORY_SYNTHETIC_TEST_PORT` to its isolated port. Run `bun scripts/test-postgres-connector-inventory.ts` only after provisioning that database and applying every migration in order. The fixture creates and removes its own login roles, closes its connections, and leaves synthetic rows for the caller's disposable database teardown.

The local PostgreSQL run passed all seven fixture groups on 2026-11-05 UTC. A fresh temporary cluster inside an existing test container received migrations `0001` through `0012` through the maintained runner. Rolling back `0012` removed its role and indexes, retained the first eleven journal entries, and reapplying it restored the exact twelve-entry journal with matching checksums. The original database was not modified. This establishes local synthetic PostgreSQL acceptance, not hosted deployment, browser cookie handling over HTTPS, or physical device behavior.

The focused Chromium test passed with mocked inventory responses. It tabs from the focused heading to the farm select, uses native keyboard type-ahead, checks the selected farm UUID and Connector display, verifies the disabled revocation action, and clears the view after a 401 response. ArrowDown/Enter and Space/ArrowDown/Enter did not select an option on the tested headless macOS Chromium; the proven path uses type-ahead. This browser fixture does not establish authentication or database authorization.
