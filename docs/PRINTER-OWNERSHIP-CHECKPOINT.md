# Printer ownership checkpoint

Work in progress: migration 0015 and the internal storage primitive are prepared. Real PostgreSQL validation, including concurrency and privilege checks and official migration reversal, is unrun. Final integrated acceptance, HTTP registration and Connector configuration remain pending. No telemetry HTTP authorization is supplied by this slice.

An independently authenticated owner or admin explicitly registers a printer key to an approved Connector in the selected farm. Keys are data, not network locations. The existing protocol permits arbitrary JavaScript strings of 1–128 UTF-16 code units; PostgreSQL cannot represent NUL or unpaired surrogates, so registration rejects those values and performs no normalization. Different farms can use the same exact key. One active assignment exists per farm and key, with at most 1,000 active assignments per Connector. Revocation permanently tombstones the assignment; reassignment requires separate revoke and register operations. A revoked Connector cannot gain a new assignment, and consumers must check the current enrollment before using any existing assignment.

Mutation locks account, session, membership, enrollment and assignment in that order. A future telemetry transaction must lock enrollment, credential, proof, sorted assignments and sorted event IDs, recheck current authority and atomically consume proof and store events. Neither this primitive nor a prior proof receipt authorizes a later telemetry write. Registration does not discover printers, access hardware or enable commands.
