# Read-only Spoolman mirror

The maintained Connector collector accepts an optional `collection.spoolman` section in its private local runtime configuration. Absence disables all Spoolman network activity. Configure a canonical HTTP(S) `origin`, UUID `farmId`, UUID `serviceId` and optional page `limit` between 1 and 200. The authenticated runtime rejects a farm different from its local credential. Origins come only from the private local file, never from signalling or browser requests.

The collector constructs and owns the inventory provider. `runConnectorAgent` and `collectIntoQueue` expose optional `onInventory` callbacks for maintained local adapters. Snapshots contain `kind`, bounded inventory and monotonic `ageMs`. `observed` means a completed observed traversal, not an atomic database snapshot or printer live status. Updates immediately mark the last known inventory `stale`. Disconnects and failed reads retain stale data. No inventory is added to printer telemetry or to an unapproved wire protocol.

REST performs GET only, rejects redirects, omits credentials, caps response pages at 256 KiB and entire traversals at 4 MiB/10,000 items/256 pages, and aborts after ten seconds. It shares the existing inventory parsers and bounded transport with the synthetic reader; that reader retains its canonical HTTP loopback guard.

The same configured origin supplies the root `/api/v1/` WebSocket. It subscribes by connecting, without application subscription messages. Spool, filament and vendor added/updated/deleted notifications invalidate the inventory. One traversal and one pending invalidation coalesce bursts, with at least one second between reads, capped failure backoff and periodic fifteen-second reconciliation. A notification during traversal prevents publication of that traversal. Reconnect performs a fresh read. WebSocket ping/pong detects silent disconnects; cached data older than thirty seconds is stale even before disconnect detection. Shutdown removes listeners, clears timers, terminates the socket and aborts HTTP.

Protocol references are the existing pinned-source revision `ff8efd517b76a4b2783f29c89e9b9fbcd8cd167b`: upstream [root WebSocket](https://github.com/Donkie/Spoolman/blob/ff8efd517b76a4b2783f29c89e9b9fbcd8cd167b/spoolman/api/v1/router.py), [event models](https://github.com/Donkie/Spoolman/blob/ff8efd517b76a4b2783f29c89e9b9fbcd8cd167b/spoolman/api/v1/models.py), and [spool REST endpoint](https://github.com/Donkie/Spoolman/blob/ff8efd517b76a4b2783f29c89e9b9fbcd8cd167b/spoolman/api/v1/spool.py). The simulator image remains digest pinned. Image-to-source metadata correlation is a separate acceptance gate. This is original MIT implementation; no upstream implementation was copied. It uses the existing MIT `ws` dependency.

No command fallback, TURN, printer requests, setup writes or remote account credentials are introduced. Linux affected unit checks, formatting/type checks and Connector build are required before merge. Mac work is source/static only.
