# Spoolman read contracts

This branch supplies a bounded local projection for vendor, filament and spool pages. It prepares E5.4a using original synthetic fixtures. There is no HTTP client, discovery, server mirror, database write or Spoolman mutation. Compatibility with an actual Spoolman API version has not yet been verified; these are provisional contracts, not a completed integration.

`parseSpoolmanVendors`, `parseSpoolmanFilaments` and `parseSpoolmanSpools` accept a supplied JSON string and trusted local context. Every resulting page carries farm ID, service ID and observation time. Numeric upstream IDs are scoped by service; identical IDs from different installations must not collide in a future mirror. Remote fields cannot supply or override this context.

Supported fields are projected explicitly; unrelated metadata is discarded. Optional values remain null instead of being replaced with guessed names, zero mass or default materials. Negative remaining weight is preserved, while negative used or initial weight is rejected by this local contract. Archived state is required and retained; consumers must not silently treat archived spools as available. No mass deduction, pricing or currency assumptions are implemented.

Pages are limited to 256 KiB and at most 200 entities; the caller's page limit can be smaller. Duplicate IDs within a page reject the whole page. Offset pagination is capped at 10,000. A full page returns a candidate next offset, and a short or empty page returns null. This convention must be checked against the selected upstream endpoint before integration. A changing remote inventory can shift offset pages: these results do not establish a consistent snapshot and must not justify deleting unseen mirror records. The future collector needs cross-page duplicate checks, total budgets and reconciliation semantics.

Names, identifiers, colors and numeric values have explicit bounds. Extra fields are retained as at most 32 opaque strings, each no longer than 4096 characters. They are not recursively JSON-decoded or executed. Prototype-related keys are rejected before schema projection. Display code still must escape all strings and avoid raw HTML rendering. Missing optional metadata can include null values; malformed required fields fail the entire page.

Errors contain fixed local codes rather than upstream payloads. The future network layer must validate status, enforce limits while streaming, authenticate as needed and restrict origins. The parser accepts already buffered strings and now uses the integrated bounded decoder to reject duplicate fields and excessive structure before projection. API version verification and simulator integration are pending. No existing service was queried to produce the fixtures or execute these tests.
