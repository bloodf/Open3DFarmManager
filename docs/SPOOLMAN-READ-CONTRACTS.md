# Spoolman read contracts

This contract describes the bounded local projection for vendor, filament and spool pages, using original synthetic fixtures. The later [inventory traversal](SPOOLMAN-INVENTORY-CHECKPOINT.md) and [loopback HTTP prototype](SPOOLMAN-HTTP-CHECKPOINT.md) build on it; the latter was checked against a pinned Spoolman API as described in its checkpoint. Discovery, server mirroring, database writes and Spoolman mutations remain outside this implementation.

`parseSpoolmanVendors`, `parseSpoolmanFilaments` and `parseSpoolmanSpools` accept a supplied JSON string and trusted local context. Every resulting page carries farm ID, service ID and observation time. Numeric upstream IDs are scoped by service; identical IDs from different installations must not collide in a future mirror. Remote fields cannot supply or override this context.

Supported fields are projected explicitly; unrelated metadata is discarded. Optional values remain null instead of being replaced with guessed names, zero mass or default materials. Negative remaining weight is preserved, while negative used or initial weight is rejected by this local contract. Archived state is required and retained; consumers must not silently treat archived spools as available. No mass deduction, pricing or currency assumptions are implemented.

Pages are limited to 256 KiB and at most 200 entities; the caller's page limit can be smaller. Duplicate IDs within a page reject the whole page. Offset pagination is capped at 10,000. A full page returns a candidate next offset, and a short or empty page returns null. The inventory traversal adds cross-page duplicate checks and total budgets. A changing remote inventory can shift offset pages: these results do not establish a consistent snapshot and must not justify deleting unseen mirror records. Reconciliation semantics remain unimplemented.

Names, identifiers, colors and numeric values have explicit bounds. Extra fields are retained as at most 32 opaque strings, each no longer than 4096 characters. They are not recursively JSON-decoded or executed. Prototype-related keys are rejected before schema projection. Display code still must escape all strings and avoid raw HTML rendering. Missing optional metadata can include null values; malformed required fields fail the entire page.

Errors contain fixed local codes rather than upstream payloads. The parser accepts already buffered strings and uses the integrated bounded decoder to reject duplicate fields and excessive structure before projection. The loopback HTTP prototype validates status and streaming limits; production authentication and origin configuration remain unimplemented. Full simulator acceptance remains pending. No existing service was queried to produce the fixtures or execute these parser tests.
