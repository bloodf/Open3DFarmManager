# Spoolman upstream contract fixtures

Run `node scripts/test-spoolman-upstream-contract.mjs` with Node 22.22.3 and Docker. The image must be present locally: `ghcr.io/donkie/spoolman@sha256:1ebb4f6a62c2e72a07f18b07ebfdbd96322f5bc2eb72570af3088f68d7c393b1` (v0.27.1, image source revision `ff8efd517b76a4b2783f29c89e9b9fbcd8cd167b`). The runner uses a fresh container with `--network none`, no published ports or mounts, and executes requests on its loopback interface. It removes the container and its anonymous volumes in `finally`. It never connects to a printer or an existing Spoolman service. A forced termination that prevents `finally` may require removing the uniquely named `o3dfm-contract-548-*` container after verifying ownership.

The [JSON corpus](../tests/fixtures/spoolman/upstream-contract/requests.json) records requests derived from the following source and responses captured on 2026-11-21 from that isolated image. Setup POSTs create original synthetic inventory and are not attributed to a client. The runner compares status and complete JSON bodies, replacing only `registered`, `first_used`, and `last_used` timestamps after checking their format. Sequence matters: the usage request changes the synthetic spool before later reads. IDs and numerical values are captured, not estimates. Fixture inputs are examples of client parameters, not recordings of the clients running. No upstream source code is copied into this project; the cited projects retain their own licenses.

The macro-to-Moonraker remote method is not replayed against Spoolman; no macro or printer was executed. The Home Assistant client above is a community integration, not Home Assistant Core. The Moonraker proxy can forward arbitrary requests, and is not itself exercised here. These fixtures cover selected community plugins, not all OctoPrint, OrcaSlicer or Home Assistant integrations. WebSocket events, plugin startup, error handling, authentication, other filters, archive transitions, and multi-client concurrency remain untested. Source inspection and direct Spoolman replay do not establish end-to-end client compatibility.

## Parity harness against the pinned image (#546, #548, #542)

`node scripts/test-spoolman-parity.mjs` replays the recorded client contracts above, the vendor, filament and spool request corpora, the auxiliary endpoints and the websocket feeds against **both** a live Spoolman v0.27.1 container and the built-in server, and compares what each answered. It needs Docker only. Nothing touches a printer or a host service.

- **Pinned image.** The Spoolman image is `ghcr.io/donkie/spoolman@<image_digest>` from `third_party/spoolman-reference/upstream.lock.json`. It is pulled by digest when it is not present locally; if the pull fails the run stops with a message naming the image. The built-in server runs on a disposable PostgreSQL 17 container pinned by digest in the script, migrated through `0089_spool_features_schema`. Every container carries the label `org.open3dfarmmanager.task=spoolman-parity-546` and is removed, with its volumes, when the run ends (the script verifies none remain).
- **Corpora.** Each corpus runs on its own fresh Spoolman container and a fresh farm, so record ids start equal. `spool-api` and `vendor-filament` are the request corpora of #540/#547 (their recorded answers are also compared with the live ones, so a recording that no longer matches the image fails); `client-contracts` is `upstream-contract/requests.json` plus `parity/client-flows.json` (the Klipper macro `SET_ACTIVE_SPOOL` flow as Moonraker issues it, the OctoPrint, Home Assistant and OrcaSlicer calls); `auxiliary-api` is `parity/aux-cases.json` (info, health, backup, settings, extra fields, locations, distinct lists, export, search, spool groups, tags, the external library served from `tests/fixtures/spoolman/aux`, and the origin guard); `websocket` is `parity/websocket-scenarios.json` (every upstream feed path, the event payloads, silent failed writes, ping replies and handshake refusals).
- **Comparison.** Status, the headers that matter (`content-type`, `x-total-*`, `content-disposition`), the body and its key order must be equal after only these normalisations: server-clock timestamps (`registered`, `date`, `created`, and `first_used`/`last_used` when stamped by the server) and, in websocket payloads, record ids by order of first appearance. Record ids are otherwise compared as they are.
- **Allowed differences.** `tests/contract/spoolman-parity/allowed-differences.json` lists every other difference. Each entry names the corpus and case, says why, and cites a sentence that must appear in `docs/compatibility/spoolman-matrix.md`. An entry that no case needs, or that a case exceeds, fails the run.
- **Provenance.** `docs/compatibility/spoolman-parity.json` records the image digest, the version Spoolman reported, the fixture hashes and the outcome counts; a run fails when it no longer matches (`SPOOLMAN_PARITY_RECORD=1` rewrites it). The full per-request report is written to `report.json` in `SPOOLMAN_PARITY_EVIDENCE_DIR` (default: a new directory under the system temporary directory, never inside the repository).

The Klipper macro itself is not executed and the clients are not run: the client fixtures are the requests those clients send, taken from the sources cited in the table above. Differences that remain by design (no tag storage, the deployment fields of `/info`, the inline `/backup` export, the extra websocket events and handshake spellings of the built-in feeds) are the entries of the allowed-differences file.
