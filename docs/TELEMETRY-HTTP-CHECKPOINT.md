# Telemetry HTTP checkpoint

Work in progress. The Node-only Connector telemetry routes remain disabled until explicitly configured by a future reviewed startup integration. The request adapter fails closed when the Node h3 event is unavailable. Real 0016 database/HTTP acceptance, enabled-route stream verification, dedicated production pool configuration and the integrated gate remain pending. This slice exposes no printer command or camera endpoint.

The Connector submits a bounded raw JSON batch to the challenge endpoint. The server generates the connection identifier and asks the 0016 transaction service for a proof bound to the exact bytes and final telemetry path. The Connector signs that challenge and submits the same bytes to the final endpoint. The atomic database service must consume the proof, check current ownership and persist the complete batch before acknowledgement. A fresh challenge is required after a lost acknowledgement, while queued event IDs stay unchanged for durable deduplication.

Node request checks use original raw target and singleton raw headers, reject cookies, Origin and content encoding, bound active readers, body size and read duration, and reject unsupported or already-consumed streams. The client uses a fixed configured endpoint, no redirects and bounded responses. Verification key files are bounded, opened without following a final symlink and checked as regular files. The explicitly activated runtime checks its database identity and uses a separate telemetry capability; database role credentials remain trusted server infrastructure.

Focused Node tests exercise real loopback HTTP for raw request rejection, bounded streams and a queue retry after an intentionally lost response. The exchange test uses a synthetic signer and storage double; it does not prove cryptographic verification, database behavior, or the Nuxt runtime adapter. Key-file tests exercise regular public keys, symlink, FIFO, oversized and malformed input. No hardware is used.

The reserved root build passed. Against the built Node app with runtime disabled, the maintained routes returned 503 for valid requests and 400 for duplicate authorization, a query string or Origin. A separately injected in-memory Nitro route, using the built portable handler wrapper, observed the original Node request, duplicate raw headers, original target and streamed bytes. That probe does not establish the enabled maintained route’s stream or database behavior.

A prepared lifecycle parses explicit opt-in configuration, owns a dedicated pool limited to three connections and provides shutdown cleanup. A Nitro startup hook invokes it and closes the pool on shutdown; Nuxt configuration is not declared yet, so it remains disabled by default. A separate disposable PostgreSQL/Node-HTTP fixture is prepared to test actual signing, stored credentials, printer ownership, queue retry and revocation, as well as capability and ownership denials for the runtime role. The fixture has not run and uses a synthetic Node event wrapper; it does not prove the enabled built-Nuxt route.
