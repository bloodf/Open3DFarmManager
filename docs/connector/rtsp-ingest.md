# RTSP ingest: source-only stage

The isolated helper is under development. Its source package and proposed module graph are not a compiled or runtime-accepted helper. No simulator, physical printer, production service or camera integration is approved by this source stage.

The planned input is private stdin: a strict versioned configuration of at most 2048 bytes, followed by EOF. The Connector resolves an opaque source handle locally and grants a nonrenewable lease of at most 30 seconds. The helper's entry deadline starts before the read. The destination is an explicit literal unicast IP and port with an RTSP path; DNS, credentials, TLS, query, fragment and multicast are excluded. A configured literal loopback simulator is permitted. Browser input does not supply source authority.

The planned profile uses one TCP RTSP connection and one H.264/90000 video track, packetization mode 1, with in-band SPS/PPS. Redirects, authentication, alternate destinations, additional tracks, reordering and unsupported SDP are terminal. It uses bounded SDP, wire, RTP and access-unit limits. The strict upstream decoder alone owns access-unit lifecycle and completion, including suppressed SEI; independent guards own wire, rate, sequence, SSRC and payload-type policy. There is no UDP, reconnection or HTTP command fallback. The Connector retains safety enforcement and browser-to-Connector WebRTC remains the live transport.

The private output protocol uses bounded Annex B records with version, flags and RTP-derived timestamps. An inherited control descriptor grants one outstanding access unit; EOF, invalid credit and pressure terminate the helper. Diagnostics contain fixed messages only. The Connector must independently enforce lease revocation, close pipes, stop and reap the child. This source stage does not establish a process-wide memory or CPU limit.

Before integration, verify the exact helper compiler-selected import closure offline without module changes, then review the linked licenses. Separately authorize bounded Go compilation and focused tests on Linux and Darwin. Prove redirect and control URI rejection, limits, timestamp and sequence wrap, SEI completion, pressure, descriptor closure and child reaping with synthetic fixtures. Any fixture network or simulator run needs separate authorization. Native moving-video acceptance and the MediaMTX source-to-image decision remain separate gates. Run `bun run check:all` before publication; publication itself remains unauthorized.
