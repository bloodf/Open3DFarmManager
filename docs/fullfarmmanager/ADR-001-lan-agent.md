# ADR-001: Keep the OpenFarm Connector as the LAN agent

**Status:** Accepted for this review.

## Context

FullFarmManager's plan describes a Go binary with outbound transport, a SQLite offline buffer, recording and replay, and a local console on port 8088. The reviewed snapshot implements a bearer-token HTTP client for reports, command long-polling and results. Its CLI rejects real-printer mode. Discovery, probing, recording and replay are stubs. The simulator can model job execution, and Go tests exercise JSON contracts and state transitions. See [snapshot checks](SNAPSHOT-CHECKS.md).

OpenFarm already maintains the TypeScript Connector, its printer adapters and its local command boundary. The [security design](../SECURITY-DESIGN.md), [command rules](../COMMAND-SECURITY.md) and [integration contract](../INTEGRATION-API.md) govern either option.

## Options

| Criterion                     | Adopt the Go agent or run it alongside the Connector                                                                                                                                             | Extend the OpenFarm Connector                                                                                                                                                                                                               |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No inbound ports              | Current polling is outbound. The planned console adds a listener and would have to be omitted. A second process adds a second trust boundary.                                                    | Keep printer connections LAN-local and require no opened inbound or forwarded ports. The browser uses direct WebRTC for live state, camera and commands, without TURN or HTTP command fallback.                                             |
| Signed commands               | Bearer-authenticated polling returns command IDs, actions and arguments. The agent would need independent issuer verification, owner scopes and durable replay protection before real operation. | Use the existing Connector admission and journal. API commands require an owner-granted scope and issuer-signed envelope. Browser commands remain on the authenticated WebRTC path.                                                         |
| Offline buffering             | SQLite buffering is planned. The snapshot provides no evidence of durable offline reconciliation.                                                                                                | Keep the local command journal. If telemetry buffering is added, bound its retention and replay only observations or outcomes with deduplication. An uncertain command needs operator reconciliation.                                       |
| Docker-only server deployment | The prototype plans Docker Compose. The Go process would still need its own lifecycle on the printer LAN, plus a server API for enrollment and polling.                                          | Keep server-side services in the Docker deployment. Keep the Connector on the printer LAN and use the existing signaling and integration endpoints.                                                                                         |
| Safety during outages         | The simulation models state transitions. It does not demonstrate local authorization or interlocks for physical devices.                                                                         | The Connector checks current printer state, local policy, authority freshness and the durable replay claim before dispatch. It returns a reason on refusal. Expired or unverifiable authority fails closed, and degraded mode is read-only. |
| Protocol coverage             | A shared driver interface and simulated fleet exist. The advertised vendor protocols are roadmap work.                                                                                           | Moonraker and Spoolman are the baseline. Bambu, Creality and Anycubic/KobraLink code already exists with model and capability limits documented in the catalogs.                                                                            |
| Test harness                  | Useful simulated transitions and contract shapes. Go vet/tests passed, while the API and browser checks did not reach assertions.                                                                | Extend the existing Connector fixtures, protocol simulators and browser command-boundary tests. Test disconnects, restart, stale state and duplicate delivery entirely against simulators or recordings.                                    |

## Decision

Use the OpenFarm Connector as the sole printer-side runtime and enforcement point. Port the Go simulator's useful behavioral cases as original TypeScript fixtures where coverage is missing, particularly externally started prints and a completed run awaiting operator collection. Import no Go runtime code, bearer command polling, simulated auto-start, local console or speculative protocol payloads.

## Consequences

New adapters expose capabilities through the Connector and start read-only. Each command capability needs independent fixture evidence for authorization, safe state and explicit refusal. Upload or command acknowledgement alone cannot establish physical completion. Keep authority validation and replay claims local even if the server is unavailable. Retain command uncertainty across restart and prohibit automatic retries. This decision leaves one deployment and test boundary to maintain and requires new simulator coverage for resin and queue behavior.
