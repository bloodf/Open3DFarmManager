## Protocol evidence

- **E1 · Chitu/CBD SDCP v3.** The board vendor publishes UDP discovery on 3000 and WebSocket on TCP 3030. Elegoo documents ChituManager workflows for the three candidates above. The board specification does not supply a model or firmware matrix. Do not infer v3 for every Wi-Fi model, including Saturn 3 Ultra, Mars 4 Ultra or Jupiter 2. A versioned discovery/status fixture is needed for model qualification. [CBD-Tech specification](https://github.com/cbd-tech/SDCP-Smart-Device-Control-Protocol-V3.0.0/blob/main/SDCP%28Smart%20Device%20Control%20Protocol%29_V3.0.0_EN.md)
- **F1 · Formlabs Local API.** PreForm or PreForm Server exposes local HTTP on a configurable host port (44388 by default in the quickstart). PreForm discovers LAN devices and can prepare jobs. The host port does not describe the printer transport. Dashboard is a separate cloud workflow. [PreForm API reference](https://developer.formlabs.com/api-reference/), [quickstart](https://developer.formlabs.com/getting-started/quickstart/), [Form 4/4L connection guide](https://formlabs.com/support/Connecting-Formlabs-SLA-printers/)
- **A1 · Anycubic Photon Workshop.** The vendor manual illustrates LAN entries for M7 Max, M7 Pro and Mono 4 Ultra. The M7 Max store listing still marks LAN transfer scheduled. Treat this as documented workflow evidence with firmware availability to verify. The MQTT endpoint named by M7 Max support is a cloud connection diagnostic and does not identify the LAN transport. [Photon Workshop manual](https://wiki.anycubic.com/photon-p1/%E5%88%87%E7%89%87%E8%BD%AF%E4%BB%B6/Anycubic%20Photon%20Workshop-EN-V1.0.0.pdf), [M7 Max network troubleshooting](https://wiki.anycubic.com/en/resin-3d-printer/anycubic-photon-mono-m7-max/device-cannot-connect-to-the-network)
