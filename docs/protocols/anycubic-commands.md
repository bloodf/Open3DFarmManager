# Anycubic LAN commands: sources for unsupported actions

Status: source-read research for issue #236. Read-only. No code is copied here. Every link points to a file at a pinned commit. Nothing below was run on a printer, so "source found" means "a public project implements or documents this wire command", not "this firmware accepts it".

Scope: the Anycubic LAN MQTT protocol (`anycubic/anycubicCloud/v1/web/printer/...`), the HTTP upload it hands out, and the Rinkhals Moonraker path where a source documents one. The "Repo status" column refers to `packages/connector/src/anycubic/control-support.ts`, `commands.ts` and `files.ts` on this branch. The repo advertises controls only for model `20024` (`supportedAnycubicActions`).

## Concerns

- **`start_print` is advertised but cannot be built.** `anycubicControls` returns `start_print` for `20024`, and `buildAnycubicControlCommand` has no matching case, so it throws "Anycubic control unavailable". This is a repo bug outside this doc's scope. A follow-up should either add the case or stop advertising it.
- **`home` and `run_macro` need Rinkhals, not LAN MQTT.** The only documented wire path is Moonraker on a rooted printer. Implementing either would add a second transport.
- **Speed levels.** The sources give three modes. The UI has four.
- **Read-only sources.** Nothing here was captured on a Kobra 3, S1 or other model. The note after kobra-connect §6 says the Rinkhals/Kobra 3 firmware uses `stop`, and that the Kobra 2 docs reference both `stop` and `cancel`.
- **Dual license on anycubic_ha_local.** The repository ships an AGPL-3.0 `LICENSE` and an MIT `LICENSE-MIT`. This doc cites both and does not decide which one covers a given file.
