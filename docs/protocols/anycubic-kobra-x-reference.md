# Anycubic Kobra X direct LAN reference

The Connector uses the printer's native LAN endpoints. The comparison below covers the wire facts exercised by a loopback fixture. The hardware capability grades in [Kobra X detail](kobra-x-detail.md) remain in force.

## Reference-matched wire behavior

[The loopback test](../../tests/node/kobra-x-orca-lan.test.ts) drives `connectKobraX` against a local HTTP server and MQTT broker using a [synthetic fixture](../../tests/fixtures/anycubic/kobra-x-orca-lan.json) and generated credentials. It covers:

- `GET /info` on HTTP port `18910` by default, followed by an empty `POST /ctrl` against the configured address. The query carries `ts` in decimal milliseconds, a six-character nonce, `did=random`, and an MD5 signature derived from the first 16 bytes of the LAN token. The response carries AES-128-CBC ciphertext, using the second 16 bytes of that token and the response IV. The recovered credentials must authenticate to the loopback broker. OpenFarm also requires the LAN control type, the Kobra X model from `/info`, a successful `/ctrl` body and a matching stored identity when one exists. [KobraXSession.cpp, credential exchange](https://github.com/bloodf/OrcaSlicer/blob/d0a76d08d3493352c6c575ee242e2d71356e400e/src/slic3r/Utils/KobraXSession.cpp#L455-L472), [KobraX.cpp, signature](https://github.com/bloodf/OrcaSlicer/blob/d0a76d08d3493352c6c575ee242e2d71356e400e/src/slic3r/Utils/KobraX.cpp#L158-L169), [KobraX.cpp, credential parsing](https://github.com/bloodf/OrcaSlicer/blob/d0a76d08d3493352c6c575ee242e2d71356e400e/src/slic3r/Utils/KobraX.cpp#L240-L274)
- Direct MQTT on port `9883` by default, with a client certificate and key and TLS 1.2 or later. The strict fixture broker accepts an authenticated MQTT 3.1.1 clean session and a QoS 0 subscription to `anycubic/anycubicCloud/v1/printer/public/{modeId}/{deviceId}/#`. OpenFarm's certificate pin is its own trust requirement. The loopback test checks that a changed pin fails before MQTT `CONNECT`. The OrcaSlicer reference configures TLS without checking the server certificate. [KobraXSession.cpp, connection](https://github.com/bloodf/OrcaSlicer/blob/d0a76d08d3493352c6c575ee242e2d71356e400e/src/slic3r/Utils/KobraXSession.cpp#L485-L517), [KobraX.cpp, MQTT login and subscription](https://github.com/bloodf/OrcaSlicer/blob/d0a76d08d3493352c6c575ee242e2d71356e400e/src/slic3r/Utils/KobraX.cpp#L277-L289), [KobraX.cpp, topics](https://github.com/bloodf/OrcaSlicer/blob/d0a76d08d3493352c6c575ee242e2d71356e400e/src/slic3r/Utils/KobraX.cpp#L341-L363)
- `info/query`, `print/query`, and `multiColorBox/getInfo` on `anycubic/anycubicCloud/v1/slicer/printer/{modeId}/{deviceId}/{type}`. These requests carry a UUID message ID, a millisecond timestamp, and `data: null`. The fixture checks reports on the bound `printer/public` tree and the resulting firmware, current job, temperature, and feeder data. OpenFarm also sends its existing `status/query` and `tempature/query` with an empty object. [KobraXSession.hpp, request defaults](https://github.com/bloodf/OrcaSlicer/blob/d0a76d08d3493352c6c575ee242e2d71356e400e/src/slic3r/Utils/KobraXSession.hpp#L67-L76), [KobraXPrinterAgent.cpp, queries](https://github.com/bloodf/OrcaSlicer/blob/d0a76d08d3493352c6c575ee242e2d71356e400e/src/slic3r/Utils/KobraXPrinterAgent.cpp#L228-L252), [KobraX.cpp, report fields](https://github.com/bloodf/OrcaSlicer/blob/d0a76d08d3493352c6c575ee242e2d71356e400e/src/slic3r/Utils/KobraX.cpp#L413-L515)

## Controls and remaining differences

- **Pause, resume, cancel, and light.** Source comparison shows the same `slicer` topic and action data for `print/pause`, `print/resume`, and `print/stop` with `taskid`, and `light/control` with the type, status, and brightness. The loopback test above covers onboarding and read-only status. [KobraXPrinterAgent.cpp, light and job controls](https://github.com/bloodf/OrcaSlicer/blob/d0a76d08d3493352c6c575ee242e2d71356e400e/src/slic3r/Utils/KobraXPrinterAgent.cpp#L399-L422), [OpenFarm actions](../../packages/connector/src/kobra-x/actions.ts)
- **Heaters and fan.** OrcaSlicer publishes idle heat on the `web` `tempature/set` topic with type `0` for the nozzle or `1` for the bed, plus both target fields. OpenFarm sends type `2` with a single target field on the `slicer` topic. Both use `slicer` `fan/setSpeed` for an idle fan adjustment. During a print OrcaSlicer also sends `web` `print/update`, while OpenFarm sends one `slicer` `print/update`. [KobraX.cpp, heater and fan controls](https://github.com/bloodf/OrcaSlicer/blob/d0a76d08d3493352c6c575ee242e2d71356e400e/src/slic3r/Utils/KobraX.cpp#L714-L745), [OpenFarm actions](../../packages/connector/src/kobra-x/actions.ts)
- **Upload and file start.** The reference uses the token from the announced upload address, `X-File-Length` and `X-BBL-Client-Type`, and separate multipart `filename` and `gcode` parts. OpenFarm's internal native upload sends one `file` part with the LAN token. Both start an existing file with `print/start`, but OrcaSlicer includes `url`, `md5`, `filetype`, `project_type`, `filesize`, `use_ams`, and additional task settings. These attributes are outside the loopback match. [KobraXSession.cpp, upload](https://github.com/bloodf/OrcaSlicer/blob/d0a76d08d3493352c6c575ee242e2d71356e400e/src/slic3r/Utils/KobraXSession.cpp#L590-L647), [KobraXHost.cpp, upload and start](https://github.com/bloodf/OrcaSlicer/blob/d0a76d08d3493352c6c575ee242e2d71356e400e/src/slic3r/Utils/KobraXHost.cpp#L66-L150), [KobraX.cpp, start payload](https://github.com/bloodf/OrcaSlicer/blob/d0a76d08d3493352c6c575ee242e2d71356e400e/src/slic3r/Utils/KobraX.cpp#L824-L844), [OpenFarm file operations](../../packages/connector/src/kobra-x/files.ts)
- **Feeder and filament selection.** The mixed holder and one-ACE topology shares holder indices `0–2` and ACE indices `4–7` in both implementations. The reference supplies color and material metadata in each `ams_box_mapping` entry and fills gaps when selecting default loaded slots. OpenFarm sends the explicit `paint_index` and `ams_index` entries and can reject an ambiguous topology. OrcaSlicer's native agent leaves direct feed and retract unimplemented. Anycubic's published ACE serial source does not establish an MQTT equivalent. [KobraX.cpp, mixed topology](https://github.com/bloodf/OrcaSlicer/blob/d0a76d08d3493352c6c575ee242e2d71356e400e/src/slic3r/Utils/KobraX.cpp#L518-L577), [KobraX.cpp, mapping entries](https://github.com/bloodf/OrcaSlicer/blob/d0a76d08d3493352c6c575ee242e2d71356e400e/src/slic3r/Utils/KobraX.cpp#L145-L154), [KobraX.cpp, slot selection](https://github.com/bloodf/OrcaSlicer/blob/d0a76d08d3493352c6c575ee242e2d71356e400e/src/slic3r/Utils/KobraX.cpp#L846-L887), [KobraXPrinterAgent.cpp, unsupported operations](https://github.com/bloodf/OrcaSlicer/blob/d0a76d08d3493352c6c575ee242e2d71356e400e/src/slic3r/Utils/KobraXPrinterAgent.cpp#L423-L443)
- **Console.** The reference parses a small set of local G-code forms and translates them to native temperature, part fan, or axis actions. The source gives no arbitrary G-code MQTT passthrough. The Connector exposes only its typed controls. [KobraX.cpp, local G-code translation](https://github.com/bloodf/OrcaSlicer/blob/d0a76d08d3493352c6c575ee242e2d71356e400e/src/slic3r/Utils/KobraX.cpp#L748-L821), [OpenFarm signed control dispatch](../../packages/connector/src/kobra-x/control.ts)
