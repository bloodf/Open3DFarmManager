## P1 Max adapter boundary

- Discovery uses `GET /info` on TCP 18910 at an explicitly configured IP. It checks the LCD model identity and returns the serial, model and reported connection mode. SSDP scanning remains outside the adapter.
- Credential negotiation fetches a fresh `/info`, checks the configured serial and the observed `net` mode, then sends one signed `POST /ctrl`. The model-specific source uses lowercase MD5 over the token prefix digest, timestamp and nonce in that order. AES-128-CBC opens the resulting credentials. The configured host controls the destination and the operation rejects HTTP redirects.
- The HTTP negotiation is plaintext and its token is available to other machines on the LAN. It does not authenticate the printer cryptographically or authorize OpenFarm commands. Keep credentials in memory and serialize exchanges per printer because `/info` refreshes the token.
- MQTT login, live status, camera, upload, start/pause/resume/cancel, temperatures, fans, material identity and levels, consumption, alerts and history are unavailable through this adapter. It sends no printer commands. The P1 Max trace advertises TCP 8883 but records a refusal. A future MQTT transport needs verified broker trust and firmware-tagged reports before it can advertise those capabilities.

The implementation uses wire facts from the [P1 Max handshake capture](https://github.com/HoffmanEngineering/printlog-bridge/blob/8a205eb/tests/fixtures/anycubic/photon_p1_max_handshake.json) and [reference handshake](https://github.com/HoffmanEngineering/printlog-bridge/blob/8a205eb/src/printlog_bridge/adapters/anycubic/handshake.py). The loopback fixture uses synthetic identifiers and secrets with the captured response shape. The implementation and fixture are original and add no dependency.
