# KobraLink commands: sources for unsupported actions

Status: source-read research for issue #236. Read-only. No code is copied here. Every link points to a file at a pinned commit. Nothing below was run against a printer or a KobraLink server, so "source found" means "the pinned upstream implements this call", not "the printer accepts it".

The upstream is the project this repo already pins in `infra/kobralink/upstream.lock`. The "Repo status" column refers to `packages/connector/src/kobralink/extended-control.ts` on this branch.

## Command rows

Actions are the `ExtendedControlAction` values in `packages/farm-protocol/src/control-actions.ts`. "Unsupported" means the KobraLink adapter does not advertise the action, so the UI shows it as "Não suportado". The advertised list is `KOBRALINK_CONTROLS` in `extended-control.ts`: pause, resume, cancel, set temperature, set fan, set light, set speed, home and start print.

## Concerns

- **The pin has no emergency stop and no printer firmware restart.** Both are reported as "no source found". The repo's own `extended-control.ts` already says so. The KobraLink restart endpoint restarts the KobraLink process, so it is not a substitute.
- **`load_filament` and `unload_filament` have a source but need hardware.** The pin shows the MQTT feed frame and the API path. Nothing in this doc confirms how a real printer responds, and the global-slot mapping in `printer-bridge.ts` is taken from the pin without a test here.
- **`run_macro` is not in the UI's known list.** `apps/farm/app/utils/farm-control-extended.ts` builds "unsupported" from `extendedActions` plus the two filament actions, so `run_macro` never appears as "Não suportado" for any vendor. Decide in a follow-up whether to add it.
