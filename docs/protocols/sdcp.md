# Elegoo SDCP

SDCP v3 discovery sends `M99999` over UDP 3000. The response may contain attributes directly in `Data` or under `Data.Attributes`. The adapter probes a locally configured IPv4 address and uses the same address for WebSocket TCP 3030 at `/websocket`. It ignores advertised addresses and checks the UDP sender, board, response topic, command and request ID. These checks correlate traffic. SDCP v3 LAN has no transport encryption or device authentication. Keep this transport within the Connector's locally provisioned LAN boundary. [CBD SDCP v3 specification](https://github.com/cbd-tech/SDCP-Smart-Device-Control-Protocol-V3.0.0)

Status uses command 0 and waits for both its acknowledgment and a board-scoped status frame. History uses command 320 and returns task IDs. Each call opens a socket, sends one request and closes on success or failure. No background polling or reconnect runs inside the adapter. Status preserves wire fields, including model-specific temperatures, fan telemetry, layer counters, resin wear counters and printer-reported errors when present. Missing fields stay absent. Consumers must interpret job states and tick units by model. Resin v3 defines ticks in milliseconds, while the stock Centauri evidence reports seconds. A resin wear counter measures component use and cannot supply resin consumption. [CBD SDCP v3 specification](https://github.com/cbd-tech/SDCP-Smart-Device-Control-Protocol-V3.0.0), [Centauri firmware observations](https://github.com/bjan/pycentauri/blob/main/docs/PROTOCOL.md)
